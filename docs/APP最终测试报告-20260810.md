## 已修复问题

### P1 扫描结果不可见且设备连接流程与小程序不一致

- 现象：设备页点击“开始查找”后没有独立手表列表，扫描期间发现的设备不能实时显示。
- 原因：App 原生层等待固定扫描周期结束后才一次返回结果，Flutter 页面又将结果渲染在设备主页下方；同时 EventChannel 载荷未正确解包。
- 修复：点击“开始查找”进入独立“添加设备”页；原生层发现设备即逐台推送；App 按设备 ID 去重、按 RSSI 排序；点击手表先停止扫描，再连接、认证和同步，成功后自动返回设备功能页。
- 回归：自动化覆盖“扫描未结束时实时显示设备 → 点击连接 → 停止扫描 → 成功返回设备页”，通过。

### P1 Release 包蓝牙扫描动态代理转换失败

- 现象：真机点击设备页“开始查找”后提示 `$Proxy4 cannot be cast to b5.d`，无法开始扫描。
- 原因：R8 将 App 的 `SearchResponse` 扫描回调与 Veepoo SDK 内部回调类水平合并，并把动态代理接口参数重写成具体类型 `b5.d`。
- 修复：Release 构建完整保留 Veepoo、Inuker 蓝牙动态代理接口以及 App 设备适配层，禁止相关类合并和类型重写。
- 构建验证：修复版 mapping 中不再存在 `-> b5.d`；Veepoo 内部回调与 App 扫描回调保持独立原始类型；Release APK 构建和 v2 签名校验通过。

### P1 蓝牙已开启但扫描不到手表

- 现象：同一距离下小程序可以发现手表，App 的设备列表始终为空。
- 原因：`vpbluetooth-1.20.aar` 未自行注册 `com.inuker.bluetooth.library.BluetoothService`，而 App 的 Manifest 也遗漏了 HBandSDK 接入文档要求宿主声明的该服务，导致 SDK 扫描代理无法稳定获得设备回调。
- 修复：在 App Manifest 中显式注册 `BluetoothService`，限制为仅本应用内部使用；未新增权限，也未修改后台接口。
- 构建验证：Release 合并 Manifest 与 APK 成品均包含该服务、`BLUETOOTH_SCAN`、`BLUETOOTH_CONNECT` 和 BLE 硬件特性；30/30 自动化测试、R8 mapping 与 APK v2 签名校验通过。

### P2 页面初始化期间重复触发构建

- 现象：进入“我的订单”时出现 `setState() or markNeedsBuild() called during build`。
- 原因：页面 `initState` 调用控制器后，控制器在首个异步等待前同步执行 `notifyListeners()`。
- 修复：订单、消息、运动记录、设备设置、AI 历史和地址加载先让出当前构建帧，再更新 UI。
- 回归：订单中心及相关初始化页面操作通过，无新增异常。
